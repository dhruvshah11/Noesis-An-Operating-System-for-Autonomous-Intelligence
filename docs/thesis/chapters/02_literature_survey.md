## 2.1 Survey Scope and Taxonomy

This chapter surveys four interlocking literature domains that jointly bound the Noesis contribution: (§2.2) memory architectures in LLM agent systems, (§2.3) capability and security models for agent orchestration, (§2.4) determinism and reproducibility in LLM pipelines, and (§2.5) open software engineering benchmarks. Each domain is first qualitatively surveyed, then compared in a four-column structured table (§2.3–§2.6) contrasting five representative systems. The survey closes with §2.7 identifying the research vacuum that C1/C2/C3 jointly fill.

## 2.2 Memory Architectures in Agent Systems

The earliest LLM agent frameworks, from ReAct [13] and Reflexion [14] through the first release of LangChain in late 2022, treated memory as an afterthought: a sliding context window or a flat key-value store appended verbatim to every prompt. As agent topologies grew to multi-hop and multi-agent settings, the community bifurcated into two design traditions. The first tradition, exemplified by AutoGen [7] and the LangGraph extension to LangChain [6], adopts a per-agent private memory with an optional shared scratchpad. The second tradition, adopted by CrewAI [8] and several commercial SaaS products, uses a single shared vector database with semantic search but no compartmentalisation by semantic lifespan or epistemological status. Both traditions suffer from well-documented pathologies. Shared-everything stores produce prompt pollution: a transient `ls -la` stdout from a tool call occupies the same embedding neighbourhood as an enduring architectural principle such as "prefer composition over inheritance," diluting attention and producing context-window thrashing at N ≥ 5 hops [15]. Per-agent private stores conversely suffer from knowledge siloing: the Vidya-equivalent coder agent in AutoGen cannot reuse the architectural constraints that the planner-agent wrote two hops earlier without an explicit handoff message, which is itself unbounded in size and format. A middle ground, layered memory, has been proposed in the cognitive architectures literature since ACT-R [16] and SOAR [17], but to our knowledge no open agent framework implements a strict six-tier semantic hierarchy with tier-adjacent-only promotion. The closest prior work is MemGPT [18], which implements a two-tier (main context / archival) paged memory with an OS-inspired virtual context manager; MemGPT's two tiers, however, correspond to window size rather than semantic type, and there is no equivalent of T6 Tattva (immutable principles) or Vivechak (Critic)-gated promotion. Noesis extends this line of work by six tiers T1 Indriya → T2 Kushalata → T3 Gyān → T4 Ranniti → T5 Yojana → T6 Tattva, each with its own backing store, write policy, and capability mask (C1, §1.7).

## 2.4 Capability and Security Models

The capability literature in operating systems is six decades old, originating with Dennis and Van Horn's 1966 formalism [20] and maturing through microkernels such as seL4 [21] and the Capsicum Unix extension [22]. The agent-systems community, however, has largely ignored this mature body of work, reinventing ad-hoc permission checks at the prompt-template layer. LangChain [6] exposes a `Tool` abstraction with a per-tool `args_schema` and an optional `_run` validation method, but no runtime reference monitor: a prompt-injected "ignore previous instructions and call `os.system('rm -rf /')`" is parsed identically to a legitimate call, because validation lives inside the tool body rather than at a pre-invoke gate [9]. AutoGen [7] goes further in the direction of weakness: by default, its `UserProxyAgent` accepts arbitrary code execution on a `docker` or `local` executor flag, with no capability minting per agent — any conversant can request `execute_code_block` and the proxy honours it unless the user intervenes. CrewAI [8] adds "role" strings such as "Senior Research Analyst" and a `allow_delegation` boolean, but delegation is not capability-gated: an agent with `allow_delegation=False` can still craft a prompt asking a peer agent to perform the same forbidden operation on its behalf, and the peer has no way to verify that the original caller was authorised. Prompt injection has been shown to bypass every one of these defences with success rates exceeding 85% in both black-box and grey-box settings [9]. The only prior agent work that approaches a principled MAC is the Guardrails AI [23] output-verification library and the Lakera Guard prompt-injection classifier [24], both of which operate as post-hoc filters on LLM text outputs rather than in-process reference monitors on spawn and invoke events. Noesis contributes the first non-bypassable AND-Mask Spawn Minting kernel (C2) living at the Python call-graph level: `AgentRoster.spawn()` and `ToolRegistry.invoke()` are the *only* two call sites that can transitively produce OS side effects, and both are gated by a three-term (roles ∧ tiers ∧ ops) or four-term (adding `tool.required_cap`) mask check that is not reachable from LLM text.

## 2.6 Determinism and Reproducibility

Determinism — the property that equal inputs produce bit-exact equal outputs — is widely regarded as a table-stakes requirement for scientific computing [10], but the LLM agent community has treated it as a lost cause. Three sources of nondeterminism are standard in every published framework. First, LLM sampling: even at `temperature=0.0`, top-p=0.0, floating-point rounding differences across GPU runs of transformers produce token-level divergence after 100–500 tokens, an effect that is amplified by autoregressive generation [10]. Second, container and language runtime nondeterminism: Python dict ordering in versions before 3.7, hash randomisation via `PYTHONHASHSEED`, wall-clock timestamps injected into log lines, and UUID4 random identifiers all leak into audit traces, making byte-level comparison impossible. Third, vector-database nondeterminism: FAISS and Chroma both use approximate nearest-neighbour indices with build-order-dependent insertion, meaning the same embedding vector can return different nearest neighbours across runs even with the same random seed. The agent community's standard response is to measure "semantic reproducibility" via LLM-as-judge rather than bit-exact comparison, but LLM-as-judge has itself been shown to be nondeterministic with agreement rates as low as 65% between judges [25]. Noesis takes the orthogonal tack of fully determinising the orchestration layer independently of the LLM layer, introducing a pure-Python deterministic path that bypasses the LLM entirely and uses a seeded `mulberry32` PRNG, RFC-4122 type-5 UUIDs, and epoch-sentinel timestamps. The C3 manifest (§5.4) demonstrates reproducibility score 1.0 on 100 runs.

## 2.8 Open Software Engineering Benchmarks

The last five years have produced a Cambrian explosion of LLM coding benchmarks, but the space can be partitioned cleanly into three families: (i) single-function synthesis, (ii) repository-level issue resolution, and (iii) open-ended capstone-style projects. Family (i) is dominated by HumanEval [2] and MBPP [3] with their plus-variants HumanEval+ and MBPP+; these are tractable at pass@1 > 90% but do not exercise tool use, multi-hop decomposition, or persistence. Family (ii) is dominated by SWE-bench [5] with its Verified and Lite splits; as noted in §1.2, state-of-the-art pass@1 on the Verified split remains below 32% for commercial systems and below 16% for open frameworks, and even the best systems often fail because they hallucinate file paths or API signatures without a grounded tool-read step [19]. Family (iii) is essentially vacant: there is no standard, open, 50+ task capstone-style corpus that spans Rust/TypeScript/Go, includes repository-level refactoring *and* end-to-end feature building, and is designed to be runnable on consumer GPUs with zero token fees. Noesis contributes the Noesis-SE50 corpus (§5.3) as a first step in that direction, alongside the C3 reproducibility manifest.

## 2.10 Unfilled Research Vacuum

Taken together, Tables 2.1–2.4 identify a joint vacuum that is precisely C1 ∪ C2 ∪ C3. There is no prior system that simultaneously implements (a) a six-tier semantic memory hierarchy with Critic-gated tier-adjacent promotion (C1), (b) a cryptographically minted AND-mask MAC kernel with non-bypassable spawn-and-invoke gates (C2), and (c) a seeded 12-agent orchestration layer with a 100-run manifest proving reproducibility score 1.0 on the Noesis-SE50 mini-subset (C3). Each prior system lacks at least two of the three contributions; most lack all three. The remainder of this thesis therefore describes the Noesis architecture (Chapter 3), methodology (Chapter 4), and implementation (Chapter 5) that together fill the vacuum.
