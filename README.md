## 🧠 Why Noesis?

Most "AI agent" repositories are a thin wrapper around a chat-completion call, a
context-window away from failure, and locked to a single provider. **Noesis is an
operating system for autonomous intelligence** — not a script, not a notebook, not
a weekend hack.

| You get… | In Noesis? |
|---|:---:|
| A 12-agent specialised roster with deterministic contracts | ✅ M7 |
| Six-tier memory with scoring, summarisation, and pruning | ✅ M5 routes (M6 LLM-backed) |
| Hybrid RAG (BM25 + dense) over PDFs, docs, and the web | ✅ M5 routes (M6 Qdrant hybrid) |
| Tool-calling with **Mandatory Access Control** (capability tokens) | ✅ M3 — 9 dry-run adapters |
| Pluggable providers: OpenAI · Anthropic · Gemini · Ollama · OpenRouter | ✅ M0 |
| Observability: latency, token/cost accounting, tool traces | ✅ M5 kernel |
| FastAPI backend + Next.js dashboard | ✅ M4 dashboard-green |
| One-command Docker deploy + matrixed GitHub Actions CI | ✅ M0 |

> 💡 **Product positioning.** CrewAI / AutoGen / LangGraph give you the agents —
> **Noesis gives you the OS** they run on: persistence, security, observability,
> deployment, and the human dashboard to operate them.

## 🧩 Feature breakdown

### 🧠 Intelligence layer

- **Planner** — mulberry32-seeded deterministic `ExecutionPlan`, 12 `AgentType`
  classifiers, topological Kahn ordering with cycle detection.
- **Research** — deterministic seeded topic draft + citation list (LLM-backed in M8).
- **Coding** — `CodingPatchReport` diff patches, AST-safe, `TaskStatus.AWAITING_INPUT`
  fallthrough until provider pipe.
- **RAG Agent** — 6-tier memory joins + jaccard keyword scorer + Qdrant dense search
  (M6 hybrid BM25).
- **Reflection, Judge, Critic, Executor, Supervisor, Orchestrator** — M7 quality
  pipeline: 5-axis rubric → candidate ranking → `{signoff|reject|replan}` gate →
  subtree spawning with subtoken mint → fan-out `all|any|majority` join.

### 🛡️ Security layer (Mandatory Access Control)

Every agent invocation carries an opaque `CapabilityToken` with `(CapabilityOp, target)`
tuples. `ToolRegistry.invoke` AND-masks against it; `AgentRoster.spawn()` raises
`PermissionDenied(op=…)` with the missing set.

```text
CapabilityOp ::= SPAWN_AGENT | TOOL_INVOKE | MEMORY_READ | MEMORY_WRITE |
                 RAG_SEARCH | RAG_UPSERT | EXECUTE_SHELL | EXECUTE_PYTHON | …
target      ::= "<registry_id>" | "shell:<glob>" | "db:read:<table>" | "*"
```

### 💾 Memory (6 tiers)

| Tier | Storage | Purpose |
|---|---|---|
| 1. **Working** | LRU cache | Per-run context, ≤ 4 KiB per slot |
| 2. **Conversation** | SQLite `messages` | Turn-level history |
| 3. **User** | SQLite `memory(user_id)` | Long-term user facts |
| 4. **Project** | SQLite `memory(project_id)` | Repo / workspace context |
| 5. **Semantic** | **Qdrant** vector store | Dense retrieval with citations |
| 6. **Episodic** | SQLite `TaskExecution` | Full tool-trace replay |

### 🔌 Tools (9 adapters, dry-run-safe)

Shell (whitelisted), PythonSandbox (AST + timeout + restricted builtins), Files
(path-escape guard), WebFetch (httpx dry-run), GitHub, Weather, Calendar
`.ics` dry-run, Email SMTP/IMAP dry-run, DB SELECT-only with auto-rollback.

### 📡 Observability

- `/health` — 3-check JSON envelope: `{ sql, qdrant, redis }`
- `/metrics` — **Prometheus** OpenMetrics counters/summaries (HTTP, tokens,
  `TaskExecution`).
- Structured **structlog** JSON in prod, coloured console in dev, secrets scrubbed
  (matches `*KEY*`, `*SECRET*`, `*TOKEN*`, `*PASSWORD*`).

### 🖥️ Dashboard (Next.js 14, 12 routes)

Sidebar, Conversations (list/detail/compose), Memory Explorer, Documents, Agents,
Metrics, Settings, Execution Timeline — all `tsc 0`, `eslint 0`, `next build`
12/12 prerendered, vitest **45/45**.

## 🪜 Prerequisites

> ✅ You only need the **minimum set** for your install path. Docker Compose path
> needs no Python on the host — **it ships its own image**.

| Prerequisite | Version | Required for | Notes |
|---|:---:|---|---|
| **Python** | `≥ 3.12` | ✅ Bare-metal backend | `3.13` recommended for perf |
| **`uv`** | `≥ 0.4` | ✅ Bare-metal installs | [Install `uv`](https://docs.astral.sh/uv/getting-started/installation/) |
| **Docker** | `≥ 26` | ✅ Compose path | [Docker Desktop](https://www.docker.com/products/docker-desktop/) |
| **Docker Compose** | `v2` | ✅ Compose path | Ships with Docker Desktop |
| **Node.js** | `≥ 20` | ✅ Dashboard build (`frontend/`) | LTS preferred; ships npm |
| **At least one LLM key** | — | ✅ Real agent runs | `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `GOOGLE_API_KEY` / or `OLLAMA_HOST` |
| **8 GB RAM + 10 GB disk** | — | ✅ Qdrant + Redis + kernel | 16 GB recommended for vector workloads |

<details>
<summary>🪟 Windows-specific notes (PowerShell)</summary>

- Enable **WSL2** for best Docker performance (Docker Desktop → Settings → General
  → Use the WSL 2 based engine).
- `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser` if scripts block `uv`
  activate.
- Python paths: use `py -3.12` launcher (it's on PATH by default with the
  python.org installer) instead of `python3`.
- SQLite comes bundled with CPython — no separate install required.

</details>

<details>
<summary>🍎 macOS-specific notes</summary>

- `brew install uv python@3.12` — we recommend `uv` over the system Python.
- Docker Desktop for Mac ships `compose`; verify with `docker compose version`.
- Apple Silicon (M1+) builds use `--platform=linux/arm64` automatically.

</details>

<details>
<summary>🐧 Linux-specific notes (Ubuntu 22.04 / 24.04)</summary>

- `curl -LsSf https://astral.sh/uv/install.sh | sh` for `uv`.
- Install Docker via the official repo, NOT `snap` — snap mounts don't play with
  bind-mounted `./data/` volumes.
- Post-install: `sudo usermod -aG docker $USER && newgrp docker`.

</details>

## ⚡ Quickstart

Three installation paths, ordered by popularity. Skip to **Option C** if you only
want to develop the dashboard UI against a mocked API.

---

### 🐳 Option A — Docker Compose (recommended)

One command boots the backend, Qdrant vector DB, and Redis — then the dashboard
builds on top.

```bash
# 1. Clone & enter
git clone https://github.com/noesis/noesis.git && cd noesis

# 2. Configure secrets (never commit this file — it's gitignored)
cp backend/.env.example backend/.env
# → edit backend/.env:  set SECRET_KEY   (openssl rand -hex 32)
#                       set OPENAI_API_KEY / ANTHROPIC_API_KEY / GOOGLE_API_KEY / OLLAMA_HOST

# 3. Boot the stack (backend + Qdrant + Redis). First run builds the multi-stage image.
docker compose -f docker/docker-compose.yml up -d --build

# 4. Inspect health (JSON envelope with sql/qdrant/redis sub-checks)
curl http://localhost:8000/health | python -m json.tool
# → {"ok": true, "data": {"status": "pass", "checks": {"sql":"pass","qdrant":"pass","redis":"pass"}}}

# 5. Interactive API docs (OpenAPI 3.1 / Swagger UI)
# → macOS/Linux:
open http://localhost:8000/docs
# → Windows PowerShell:
Start-Process http://localhost:8000/docs

# 6. Boot the dashboard (separate shell)
cd frontend
npm install
npm run dev    # → http://localhost:3000
```

To tear down **without losing data** (volumes stay):
```bash
docker compose -f docker/docker-compose.yml down
```
To wipe the DB / vectors too: `docker compose down -v --remove-orphans`.

---

### 🧪 Option B — Bare metal (backend-only, SQLite)

Pick this for fast iteration on the kernel without Docker.

```bash
# 1. Env
cd backend
uv venv --python 3.12 .venv
# → POSIX:
source .venv/bin/activate
# → Windows PowerShell:
# .venv\Scripts\Activate.ps1

# 2. Install (editable + dev extras)
uv pip install -e ".[dev]"

# 3. Secrets
cp .env.example .env
$EDITOR .env    # set SECRET_KEY + provider keys

# 4. Run. SQLite is used for RDB; in-memory stub for Qdrant & Redis by default.
uvicorn noesis.api.main:app --reload --host 0.0.0.0 --port 8000

# 5. Smoke
curl -sS http://localhost:8000/ | python -m json.tool
```

---

### 🎨 Option C — Frontend only (mocked data)

```bash
cd frontend
npm install
# Vitest units first
npm run test -- --run       # → 45 / 45
# Build to confirm prerender
npm run build               # → ✓ 12 / 12 static routes
npm run dev                 # → http://localhost:3000  (uses fixtures, no backend needed)
```

## 📘 Usage examples

> 💡 Every snippet below is runnable against `http://localhost:8000` after Option A
> or Option B. Snippets use the **Python SDK** (ships with `pip install noesis`)
> and **cURL** for maximal portability.

### 1️⃣ Plan a goal → execute end-to-end (SDK)

```python
from noesis import NoesisClient, CapabilityOp, capability_token

# 1. Client (JWT omitted — uses default dev-token with full caps)
client = NoesisClient(base_url="http://localhost:8000")

# 2. Start a conversation
conv = client.conversations.create(title="Build me a todo list CLI in Rust")

# 3. Ask the Planner → execution plan (deterministic, no LLM needed)
plan = client.runs.plan(
    conversation_id=conv.id,
    goal="Write a Rust CLI tool that manages a to-do list with add/list/done.
          Emit crates.io Cargo.toml, src/main.rs, and a short README.",
)
print(f"Planner returned {len(plan.steps)} steps")  # → 12
for s in plan.steps:
    print(f"  [{s.order:>2}] {s.agent_type.value:<12}  {s.status.value}")

# 4. Execute via AgentRuntime (topological order, MAC-gated, SQL TaskExecution rows)
run = client.runs.execute(
    conversation_id=conv.id,
    plan_id=plan.id,
    token=capability_token(
        # Whitelist the ops the user wants this run to perform:
        (CapabilityOp.TOOL_INVOKE, "file:read:*"),
        (CapabilityOp.TOOL_INVOKE, "file:write:*"),
        (CapabilityOp.MEMORY_WRITE, conv.id),
    ),
)
print(run.final_report[:400])  # → CodingPatchReport diff + signoff / judge rank
```

### 2️⃣ Same flow, curl + jq (no SDK needed)

```bash
# --- Step 1. Plan ---
PLAN=$(curl -sS -X POST http://localhost:8000/v1/runs/plan \
  -H 'Content-Type: application/json' \
  -d '{
    "conversation_id": "conv_demo",
    "goal": "Explain RAG in 3 sentences, then cite 2 sources.",
    "max_steps": 8
  }')
echo "$PLAN" | jq '.data.steps | length'   # → 8

# --- Step 2. Execute ---
RUN=$(curl -sS -X POST http://localhost:8000/v1/runs/execute \
  -H 'Content-Type: application/json' \
  -d "{ \"conversation_id\": \"conv_demo\",
        \"plan_id\": \"$(echo $PLAN | jq -r .data.id)\",
        \"capabilities\": [{\"op\":\"tool_invoke\",\"target\":\"*\"}] }")
echo "$RUN" | jq '.data.final_status, .data.final_report'
```

## 📖 API reference

OpenAPI 3.1 spec is served **live** by the running kernel at
[`/openapi.json`](http://localhost:8000/openapi.json). Interactive Swagger UI is
at [`/docs`](http://localhost:8000/docs); ReDoc at [`/redoc`](http://localhost:8000/redoc).
Both are disabled automatically when `APP_ENV=production`.

### Route group index

| Group | Prefix | Count | Typical first call |
|---|---|:---:|---|
| **Kernel & root** | `/`, `/health`, `/metrics` | 3 | `GET /health` |
| **Conversations** | `/v1/conversations` | 7 | `POST /v1/conversations` |
| **Agents** | `/v1/agents` | 2 | `GET /v1/agents` |
| **Runs (plan + execute)** | `/v1/runs` | 3 | `POST /v1/runs/plan` |
| **Documents** | `/v1/documents` | 5 | `POST /v1/documents/upload` |
| **Memory** | `/v1/memory` | 3 | `POST /v1/memory/query` |
| **UAP (universal agent protocol)** | `/v1/uap` | 3 | `POST /v1/uap/transports/inproc` |

### 1. Root & health

```http
GET /              → { ok, name, version, env, docs, health, request_id }
GET /health/livez  → 200  (always pass — for kubelet liveness)
GET /health/readyz → 200 | 503  (sub-checks: sql, qdrant, redis)
GET /metrics       → text/plain, Prometheus OpenMetrics (HTTP, tokens, TaskExecution)
```

### 2. Conversations

```python
# Every payload is wrapped in the standard envelope: { ok, data, error? }
GET    /v1/conversations?user_id=&limit=&cursor=    → list (Paginated)
POST   /v1/conversations                           → { title, user_id, metadata } → Conversation
GET    /v1/conversations/{id}                      → Conversation
PATCH  /v1/conversations/{id}                      → partial update (title / metadata)
DELETE /v1/conversations/{id}                      → soft-delete (masked)
GET    /v1/conversations/{id}/messages             → history
POST   /v1/conversations/{id}/messages             → append (user or assistant)
```

### 3. Agents

```http
GET  /v1/agents
     → manifest list: [{ name, agent_type, description, required_capabilities }] × 12
POST /v1/agents/invoke
     body: { agent_type, input, ctx_token, capabilities }
     → { status, report, report_type, artifacts, status_history }
```

### 4. Runs

```http
POST /v1/runs/plan
     body: { conversation_id, goal, max_steps }
     → ExecutionPlan { id, steps[] }

POST /v1/runs/execute
     body: { conversation_id, plan_id, capabilities[] }
     → RunResult { id, final_status, final_report, executions[] }

GET  /v1/runs/{id}/executions
     → full TaskExecution audit (tool_trace, tokens_in/out, cost_usd, duration_ms)
```

### 5. Documents

```http
POST /v1/documents            JSON metadata (no file)
POST /v1/documents/upload     multipart/form-data: file + title + user_id + source_uri
GET  /v1/documents?user_id=&cursor=
GET  /v1/documents/{id}
DELETE /v1/documents/{id}
```

### 6. Memory

```http
GET    /v1/memory?tier=&user_id=&conversation_id=
POST   /v1/memory/query    { query, tier, top_k, min_importance } → jaccard score
POST   /v1/memory/compress { tier, user_id, older_than_days, ratio } → pruned_count
```

### 7. UAP v1 (universal agent protocol)

> 🔌 Experimental. Plugins and third-party kernels use this to bind capability
> tokens over process / host boundaries.

```http
GET  /v1/uap/transports                    → [ { id, protocol, locality } ]
POST /v1/uap/transports/inproc             → { bind_id, token_b64, expires_at }
POST /v1/uap/envelope/send                 → { accepted, payload_sha256 }
```

## 🛟 Troubleshooting

Most issues fall into one of seven buckets. If none apply, open a bug report using
the template — it asks for the exact info we need to reproduce.

<details>
<summary>🧪 1. "Tests fail on first run: permission denied / sqlite busy"</summary>

- Wipe the `backend/.pytest_cache` and `backend/.ruff_cache` dirs.
- Ensure **no other** `uvicorn` / `docker compose` instance holds `data/noesis.db`.
  On Windows, `Handle64` (Sysinternals) can hunt the file lock.
- If using **Py 3.13** and a C-extension module fails to load: switch to `3.12` or
  re-run `uv pip install -e ".[dev]"` (it recompiles wheels).

</details>

<details>
<summary>🐳 2. Docker Compose: backend restarts in a loop (log says "DB not ready")</summary>

- Default `depends_on` uses `condition: service_healthy`, so the backend waits for
  `qdrant`/`redis` healthchecks **then** boots. If you still see a loop:
  ```bash
  docker compose -f docker/docker-compose.yml down
  docker compose pull
  docker compose up -d --build
  ```
- Check `docker compose logs qdrant`. If Qdrant crashes on arm64 Mac/Linux: add
  `platform: linux/amd64` under the `qdrant` service and retry.

</details>

<details>
<summary>🔐 3. "PermissionDenied: spawn_agent:*" when calling AgentRoster.spawn</summary>

You are missing the `(CapabilityOp.SPAWN_AGENT, target)` tuple in your token. The
deny error message prints the **missing set** verbatim — copy those into your
token mint. `AgentRoster.get()` is intentionally capability-less (for unit tests
and dry-runs) — prefer it during local dev.

</details>

<details>
<summary>📦 4. `ModuleNotFoundError: No module named 'noesis'`</summary>

You installed without the `-e` flag, or the venv is not active. Re-run from the
`backend/` directory:

```bash
uv pip install -e ".[dev]"          # editable install picks up local edits
python -c "import noesis; print(noesis.__version__)"
```

</details>

<details>
<summary>🧠 5. Agents return `AWAITING_INPUT` instead of a real answer</summary>

This is **by design** — M7 agents are deterministic **seeds** with exact contracts.
They avoid LLM calls so tests never flake. Flip to LLM-backed (M8 behavior):

1. Set `NOESIS_AGENT_MODE=llm` in `backend/.env`
2. Restart `uvicorn`; the agent classes will use `NoesisClient` provider abstraction
   via `get_provider(provider_name=...)`.

</details>

<details>
<summary>📝 6. `PydanticValidationError: field required` on CriticReport / SupervisorReport</summary>

You wrote a FAILED fast-path branch that doesn't populate required fields. Fix
pattern: add safe defaults in the model (example in `agents/core.py`):

```python
overall_quality: float = Field(default=0.0, ge=0.0, le=1.0)
praise: list[str]          = Field(default_factory=list)
improvements: list[str]    = Field(default_factory=list)
```

</details>

<details>
<summary>🧱 7. Windows: `.\.venv\Scripts\Activate.ps1` is not digitally signed</summary>

Per the [Windows prerequisites](#%EF%B8%8F-windows-specific-notes-powershell):

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

You only need to run this once.

</details>

Still stuck? Open [an issue](https://github.com/noesis/noesis/issues/new?labels=bug)
with:
- the output of `noesis version` (or `python -c "import noesis; print(noesis.__version__)"`)
- the failing command + its logs wrapped in a triple-backtick code block
- your OS + Python version

## 🙋 FAQ

**Why not just use CrewAI / AutoGen / LangGraph examples?**
> Those are fantastic primitives. Noesis is the **production box** you actually
> deploy around them: provider abstraction, six persistence tiers, memory
> lifecycle, capability-based security, observability, CI, Docker, the dashboard —
> and a fully-specified 12-agent architecture. CrewAI gives you the crew; Noesis
> gives you the OS.

**Why Qdrant over pgvector / Chroma / FAISS?**
> Qdrant is production-ready out of the box: disk persistence, filtering
> performance, sharding, built-in quantization, first-class async client.
> pgvector couples vector I/O to your relational write path (bad at scale). FAISS
> is ephemeral in-process only. Chroma is still moving through early-production
> milestones.

**Why `uv` over Poetry?**
> `uv` is 10–100× faster, first-class PEP 621 (no custom lockfile dialect to
> learn), and is fast becoming the standard.

**Why SQLite in dev?**
> Zero-config onboarding. Swap `DATABASE_URL=postgresql+asyncpg://…` for
> production and **the exact same models + queries continue to work** — SQLAlchemy
> 2.0 abstracts the dialect gaps for us.

**Can I run agents with *no* LLM key?**
> Absolutely — this is the default for M7. All 12 agents ship deterministic,
> seeded implementations that fulfil their typed contracts, so `pytest`,
> dashboard, and the kernel runtime all work 100% offline. Flip
> `NOESIS_AGENT_MODE=llm` once you add a provider key.

**Where is NoesisOS (the bare-metal SKU)?**
> On the [Roadmap](#-roadmap) at **M8+**. NoesisOS will ship as a bootable image
> (oci → ISO) with the kernel, a local dashboard, and zero-trust inter-kernel
> UAP transports.
